WSO2 Integrator provides support for building, deploying, securing, and observing integrations on Amazon Web Services ([AWS](https://aws.amazon.com/)). You can connect to AWS services, use Amazon Bedrock for AI capabilities, deploy integrations on AWS compute services, securely access AWS resources using IAM roles, and monitor integrations using AWS observability services.
This page provides an overview of the capabilities and resources available for using WSO2 Integrator with AWS.


![Architecture diagram: an event in AWS (SQS or Lambda) triggers WSO2 Integrator, which runs on ECS, EKS, EC2 or Lambda, optionally calls Amazon Bedrock for AI, and talks to AWS services like S3, DynamoDB, SNS, SES and Redshift -- secured by IAM roles and watched with CloudWatch, X-Ray and Prometheus.](../../assets/img/aws/architecture-light-v5.1.png)

## [New to AWS?](https://docs.aws.amazon.com/)

Here are four AWS concepts you'll see throughout this guide

### ECS

A fully managed container orchestration service for running your integration, used by the recommended deployment below.

[ECS →](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/Welcome.html)

### IAM role

An identity AWS gives your integration, so it can use AWS without access keys in your code.

[IAM role →](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles.html)

### VPC

An isolated virtual network within AWS where you run and connect your resources.

[VPC →](https://docs.aws.amazon.com/vpc/latest/userguide/what-is-amazon-vpc.html)

### Amazon Bedrock

The AWS service for using AI models from several providers through one API.

[Amazon Bedrock →](https://docs.aws.amazon.com/bedrock/latest/userguide/what-is-service.html)

## Build for AWS {#build}



Decide how your integration interacts with AWS, add AI with Amazon Bedrock, and
use Bedrock for AI assisted development.





### Connect with AWS



Most teams start with a connector.

### Connect to AWS services

Add a connector from the palette and sign in with the IAM role of wherever it runs.

- [Browse AWS connectors](https://wso2.com/integration-platform/docs/connectors/catalog)

### React to AWS events

Start an integration when a message lands in an SQS queue, or when an event invokes an AWS Lambda function.

- [SQS listener](../develop-and-test/integration-artifacts/event-driven-integration/aws-sqs.mdx)
- [Lambda event handlers](../deploy-and-run/self-hosted/serverless-deployment.mdx#aws-lambda)

### Call any AWS API

No connector for a service? Call its API directly - request signing (SigV4), Region and FIPS endpoints are handled for you.

- [Call AWS APIs](../deploy-and-run/secure/aws-access.mdx#call-aws-apis-without-a-connector)




###  Build AI applications with Amazon Bedrock {#ai}



Use AI models hosted on AWS, so your data stays in your AWS account.

### Use Bedrock models

Call chat models and create embeddings through Amazon Bedrock, configured as a model or embedding provider.

- [Model providers](../develop-and-test/integration-artifacts/ai-integrations/ai-building-blocks/model-providers.mdx#aws-bedrock)
- [Embedding providers](../develop-and-test/integration-artifacts/ai-integrations/ai-building-blocks/embedding-providers.mdx#aws-bedrock)
- [Authentication](../develop-and-test/integration-artifacts/ai-integrations/ai-building-blocks/model-providers.mdx#aws-credential-options)

### Answer from your own data (RAG)

Let AI answer from your documents using retrieval-augmented generation, with your source documents in S3.

- [Bedrock knowledge bases](../develop-and-test/integration-artifacts/ai-integrations/ai-building-blocks/knowledge-bases.mdx#aws-bedrock)
- [S3 Vectors](../develop-and-test/integration-artifacts/ai-integrations/ai-building-blocks/vector-stores.mdx#amazon-s3-vectors)
- [S3 data loader](../develop-and-test/integration-artifacts/ai-integrations/ai-building-blocks/data-loaders.mdx#aws-s3-text-data-loader)

### Run agents on Bedrock AgentCore

Deploy AI agents to AgentCore and give them tools through AgentCore Gateway.

- [Deploy](../deploy-and-run/self-hosted/containerized-deployment.mdx#amazon-bedrock-agentcore-runtime-deployment)
- [Authentication](../deploy-and-run/secure/authentication.mdx#agents-on-amazon-bedrock-agentcore-runtime)
- [Tracing](../observe/tracing.mdx#on-amazon-bedrock-agentcore-runtime)

### Give agents a memory

Store conversation memory in DynamoDB so agents remember earlier messages.

- [DynamoDB](../develop-and-test/integration-artifacts/ai-integrations/agents/memory.mdx#creating-an-amazon-dynamodb-short-term-memory-store)




### Use Amazon Bedrock for AI-assisted development



Bedrock also powers AI features built into WSO2 Integrator itself.

### Copilot with Amazon Bedrock

Sign in to WSO2 Integrator Copilot with your own Amazon Bedrock credentials.

- [Sign in with Bedrock](../editor/copilot/copilot.mdx#sign-in-from-the-copilot-welcome-screen)
- [How Copilot uses Bedrock](../editor/copilot/copilot-architecture.mdx#amazon-bedrock)

### AI-assisted migration

Use Bedrock models to help migrate existing integrations onto WSO2 Integrator.

- [From MuleSoft](../migrate/from-mulesoft.mdx#step-5-ai-enhancement)
- [From TIBCO](../migrate/from-tibco.mdx#step-5-ai-enhancement)

[Amazon ECS on Fargate Recommended →](../deploy-and-run/self-hosted/containerized-deployment.mdx#amazon-ecs-deployment)


### Amazon EKS

Choose this if your team already runs Kubernetes.

[Amazon EKS →](../deploy-and-run/self-hosted/containerized-deployment.mdx#amazon-eks-deployment)

### Amazon EC2

Choose this if you want a virtual machine you fully control.

[Amazon EC2 →](../deploy-and-run/self-hosted/vm-deployment.mdx#run-on-amazon-ec2)

### AWS Lambda

Choose this for short, event-driven jobs that run only when needed.

[AWS Lambda →](../deploy-and-run/self-hosted/serverless-deployment.mdx#aws-lambda)

## Secure on AWS {#secure}




Follow these three practices from day one.

### Use IAM roles, not keys

Your integration picks up the role of wherever it runs - nothing secret lives in code.

- [Default credential chain](../deploy-and-run/secure/aws-access.mdx#use-the-default-credential-chain)
- [Attach an IAM role](../deploy-and-run/secure/aws-access.mdx#attach-an-iam-role)
- [Cross-account access](../deploy-and-run/secure/aws-access.mdx#access-resources-in-another-aws-account)

### Keep secrets out of code

Load passwords and settings from AWS Secrets Manager or SSM Parameter Store.

[Keep secrets out of code →](../deploy-and-run/secure/secrets-encryption.mdx#aws-secrets-manager)

### Keep traffic private

Reach AWS services through VPC endpoints, with FIPS and dual-stack options.

[Keep traffic private →](../deploy-and-run/secure/aws-access.mdx#keep-aws-traffic-inside-your-vpc)

## Observe in AWS {#observe}




Send logs, traces and metrics to the AWS tools you already use.

### Logs

Collect logs in Amazon CloudWatch Logs.

- [CloudWatch Logs](../observe/logging.mdx#send-logs-to-amazon-cloudwatch-logs)

### Traces

Follow each request end to end with AWS X-Ray.

- [AWS X-Ray](../observe/tracing.mdx#choose-a-tracing-backend)

### Metrics

Track performance in Amazon Managed Service for Prometheus.

- [Managed Prometheus](../observe/metrics.mdx#send-metrics-to-amazon-managed-service-for-prometheus)
